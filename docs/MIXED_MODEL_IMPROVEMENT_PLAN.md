# Mixed 모델 성능 개선 계획

## 현재 문제점 분석

1. **이미지 크기가 너무 작음 (192x128)**
   - 작은 객체 탐지 어려움
   - 카메라 하단만 잡는 현상 발생

2. **Recall이 매우 낮음 (0.21)**
   - 많은 객체를 놓치고 있음
   - Confidence threshold가 높을 수 있음

3. **데이터 증강이 모두 비활성화됨**
   - 모델의 일반화 능력 저하
   - 과적합 위험

4. **학습 에폭이 부족할 수 있음 (15 epochs)**
   - Loss가 계속 감소 중이었음

## 개선 방안 (우선순위별)

### 🔴 1순위: 이미지 크기 증가 (가장 중요!)

**현재:** `imgsz: 192`  
**제안:** `imgsz: 320` 또는 `imgsz: 416`

**이유:**
- 작은 객체 탐지 능력 향상
- 더 많은 공간 정보 활용
- 카메라 하단 편향 문제 완화

**트레이드오프:**
- 메모리 사용량 증가 (배치 크기 조정 필요)
- 학습 시간 증가

**권장 설정:**
```python
imgsz: 320  # 192 -> 320 (약 2.8배 해상도 증가)
batch: 2    # 메모리 허용 시 4로 유지 가능
```

---

### 🟠 2순위: 에폭 수 증가

**현재:** `epochs: 15`  
**제안:** `epochs: 30` 또는 `epochs: 50`

**이유:**
- Epoch 13에서 최고 성능 (mAP50: 0.51)
- Loss가 계속 감소 중이었음
- 더 많은 학습으로 성능 향상 가능

**주의:**
- Early stopping patience 조정 필요
- 과적합 모니터링

---

### 🟡 3순위: 데이터 증강 재활성화 (조심스럽게)

**현재:** 모두 비활성화 (mosaic=0, mixup=0, copy_paste=0)  
**제안:** 점진적 재활성화

**옵션 A: 안전한 증강만 활성화**
```python
mosaic: 0.3      # 낮은 확률로 시작
mixup: 0.0       # 유지 (이전 에러 원인)
copy_paste: 0.0  # 유지
fliplr: 0.5      # 이미 활성화됨
degrees: 5.0     # 작은 회전 추가
translate: 0.1    # 이미 활성화됨
scale: 0.5       # 이미 활성화됨
```

**옵션 B: Mosaic만 재활성화 (더 보수적)**
```python
mosaic: 0.5      # 중간 확률
mixup: 0.0       # 유지
copy_paste: 0.0  # 유지
```

**주의:**
- 이전에 mosaic에서 빈 배치 에러 발생
- 데이터셋 크기와 품질 확인 필요

---

### 🟢 4순위: 모델 크기 증가

**현재:** `yolov8n.pt` (nano - 가장 작음)  
**제안:** `yolov8s.pt` (small)

**이유:**
- 더 많은 파라미터 = 더 복잡한 패턴 학습
- 성능 향상 가능

**트레이드오프:**
- 학습 시간 증가
- 메모리 사용량 증가
- 추론 속도 약간 감소

---

### 🔵 5순위: 학습률 및 Loss 가중치 조정

**현재:**
- `lr0: 0.0001`
- `box: 7.5`, `cls: 0.5`, `dfl: 1.5`

**제안:**
```python
lr0: 0.001      # 약간 증가 (더 빠른 학습)
box: 7.5        # 유지
cls: 1.0        # 증가 (분류 중요도 증가)
dfl: 1.5        # 유지
```

---

### 🟣 6순위: Confidence Threshold 조정

**현재:** `conf: 0.25` (추론 시)  
**제안:** `conf: 0.15` 또는 `conf: 0.20`

**이유:**
- Recall 향상 (더 많은 객체 탐지)
- Precision은 약간 감소할 수 있음

---

### ⚪ 7순위: 배치 크기 증가 (메모리 허용 시)

**현재:** `batch: 4`  
**제안:** `batch: 8` 또는 `batch: 16`

**이유:**
- 학습 안정성 향상
- 더 나은 gradient 추정

**주의:**
- 이미지 크기 증가 시 메모리 부족 가능
- OOM 에러 주의

---

## 추천 개선 조합 (단계별)

### 🎯 Phase 1: 빠른 개선 (낮은 리스크)
```python
imgsz: 320          # 192 -> 320
epochs: 30          # 15 -> 30
batch: 2            # 메모리 고려
conf: 0.20          # 추론 시
```

**예상 효과:**
- mAP50: 0.42 -> 0.50+ (목표)
- Recall: 0.21 -> 0.30+ (목표)

---

### 🎯 Phase 2: 중간 개선 (중간 리스크)
```python
imgsz: 320
epochs: 50
batch: 2
mosaic: 0.3          # 재활성화
conf: 0.20
```

---

### 🎯 Phase 3: 고급 개선 (높은 리스크)
```python
imgsz: 416          # 더 큰 이미지
epochs: 50
batch: 2
model: yolov8s      # 모델 크기 증가
mosaic: 0.5
conf: 0.15
```

---

## 실행 계획

1. **Phase 1 실행** → 결과 확인
2. **성능 향상 확인** → Phase 2 진행 여부 결정
3. **필요 시 Phase 3** → 최종 성능 확보

- **Recall**: 0.21 → 0.35+ (목표)
- **Precision**: 0.60 → 0.55+ (약간 감소 허용)
- **실제 동영상에서의 탐지 품질** (가장 중요!)

---

## 주의사항

1. **메모리 관리**
   - 이미지 크기 증가 시 배치 크기 조정 필수
   - OOM 에러 발생 시 배치 크기 감소

2. **학습 시간**
   - 이미지 크기와 에폭 증가로 학습 시간 2-3배 증가 예상

3. **데이터 증강**
   - 이전 에러 재발 가능성
   - 작은 확률로 시작하여 점진적 증가

4. **과적합 모니터링**
   - Validation loss와 train loss 차이 확인
   - Early stopping 활용
